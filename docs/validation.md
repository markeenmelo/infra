# Validation scope and implementation record

Current commands use [native devenv](development.md). Historical sections retain the exact `just`/devShell commands run at those checkpoints; they are evidence, not current entry points.

## Choose validation scope

Use the actual staged **and** unstaged diff, not its filename alone. Code, configuration, dependencies/locks, tests, policy data and ciphertext changes require the canonical checks below. After a substantive change to a commissioned host's configuration/closure, also run `devenv shell ready HOST` and `devenv shell build HOST`. Run this full path once on the final coherent candidate; a later prose-only correction does not invalidate unchanged code/build evidence. Deployment preflight still requires full checks and separate operation authorization.

### Documentation-only changes

For prose, links, status records, `AGENTS.md` and skill instructions with no runtime-input change:

1. Inspect `git status --short`, the intended diff and any staged diff. Run `git diff --check` and `git diff --cached --check`; stage only individually reviewed paths if staging is needed.
2. Check changed relative links/anchors and reconcile status claims against [the authoritative dated host status](hosts.md#current-status). Keep historical evidence dated; do not present it as current acceptance.
3. Validate changed executable snippets **without executing their operations**: use `bash -n` and ShellCheck on complete shell blocks; parse JSON strictly; parse Nix and evaluate its option shape against the selected capability using isolated, evaluation-only data. Review command names/flags and surrounding authorization boundaries. Incomplete illustrative fragments need explicit context, not invented hardware/credentials to make them runnable.
4. Report those checks and any unresolved snippet/link/status issue. No formatter, fleet evaluation, canonical check, readiness command or host build is required solely for documentation edits: the formatter does not check Markdown. Do not run a snippet's deployment, storage, credential or live-service command as a documentation test.

## Canonical command

```sh
nix run --no-update-lock-file .#devenv -- tasks run repo:check-full
```

With the locked CLI available, use **`devenv tasks run repo:check-full`** (default `before` dependency mode), or `devenv test`. Never use `--mode single` for these gates. `devenv tasks run repo:fmt` is the explicit formatting mutation. **`repo:check` is the fast inner gate** — task/lock/tooling contract, treefmt (`--ci`), statix, the ciphertext guard and the whole-fleet inventory, in seconds — for use while iterating. `repo:check-full` adds the evaluation oracle (`repo:evaluate`), the ciphertext regression suite and the full `nix flake check -L`; it remains the gate for final candidates, deployment preflight and `devenv test`. Neither gate is destructive: no mounting, provisioning, installation, SSH connection or activation. Nix may fetch inputs/binaries and build store derivations. Stage intended new files first so a Git flake includes them.

### Check ownership

`modules/validation.nix` is the shared typed fixture/inventory harness. Storage, access, deployment, desktop/Wi-Fi, Tailscale and fleet concerns own their report/check implementations; smaller kernel, nh, printing and workstation predicates remain beside those features. Fixture facts are contributed per selected capability, never copied into real hosts. `validation.hosts` forces every registered real-host predicate; `checks.fleet-evaluation` independently inventories the eight reports and 22 built checks before forcing context-free report serialization. This prevents a removed owner from silently shrinking the aggregate. The host module type also has an isolated wrong-class regression.

The independent track oracle in `modules/validation.nix` deliberately repeats the three required track decisions. Changing a host's metadata alone must fail. Changing evaluator wiring to the other input must also fail even if reported metadata looks correct. A numbered stable input must not be silently replaced with an unstable branch alias.
