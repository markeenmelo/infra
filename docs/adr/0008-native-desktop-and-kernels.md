# ADR 0008 — Native desktop modules, private Wi-Fi and stock 7.x kernels

- Status: accepted
- Date: 2026-09-09
- Amends [ADR 0007](0007-thinkpad-desktop.md), [track policy](0002-nixpkgs-tracks.md) and the earlier kernel recommendation in [research](../research.md)

## Context

The user now explicitly requests reusing the current Ghostty, Herdr, Zed, Zen, Pi and Bitwarden preferences, replacing Foot/Firefox and the text greeter, fingerprint login/locking/sudo, SOPS-managed home/campus Wi-Fi and latest available 7.x kernels. The approved optional tools are file/archive/document/image utilities, system/audio/network controls, Bluetooth, KDE Connect, printing/scanning and shell conveniences. No media player was selected. This does not authorize activation, enrollment, secret decryption, connecting networks or changing storage.

## Decision

Remove unused stable Home Manager. `modules/fleet.nix` imports the existing unstable HM pin only for the explicit `hyprland` capability and rejects that capability on stable. Stable Nixpkgs remains required for servers; Dino also has no HM evaluation. Retain class-checked deferred modules, host `pkgs`, `useGlobalPkgs`, `useUserPackages`, release checks and file-collision detection. Use native HM Hyprland Lua settings, Noctalia, Ghostty, Herdr, Zed and Pi options. Lua dispatcher expressions still require the native inline-value escape hatch. Preserve Noctalia's isolated profile and one session owner.

Use native NixOS Noctalia Greeter with greetd underneath and the UWSM session. Narrow fingerprint PAM to a dedicated graphical stack and sudo, ordered **password first**. Greeter empty submission requests an alternative authenticator; it never permits an empty account password. Retain deny rules, ordinary console/SSH policy and keyring handling. Noctalia's lockscreen drives fprintd independently alongside password entry. Fingerprint templates and greeter/Bluetooth/printer system state have scoped persistence; `/home` needs no duplicate binds.

Port reviewed application preferences and public pinned extension manifests, not credentials, vaults, browser profiles or arbitrary old desktop settings. Zen is absent from the locked Nixpkgs. It was initially a source-only exact-URL pin; the requested refinement makes it a normal **`zen-browser` flake input** with URL `github:youwen5/zen-browser-flake` and an unstable follows link. Rename the desktop-only HM input to **`home-manager`**, URL `github:nix-community/home-manager`, retaining its unstable follow. Both use default branches with exact revisions only in `flake.lock`; no dependency revision changed during this refinement. Continue instantiating Zen's recipe with the host's own `pkgs`, not upstream package outputs or overlays. Retain its small, researched Firefox-wrapper passthru adapter and existing pinned XPIs. Pi retains the pinned extension bundle and safe project-trust/rewind settings; its existing providers require a two-package unfree allowance, not blanket unfree policy.

Use native NetworkManager `ensureProfiles` with system-owned, root-only runtime secrets (`*-flags = 0`), avoiding competition between two secret agents or a Noctalia patch. A small offline-tested adapter escapes raw SOPS scalars for both the private systemd environment file and GLib keyfiles. Reuse MN-Home's existing encrypted PSK/profile UUID. SenecaNET uses PEAP/MSCHAPv2, the system CA bundle and `senecapolytechnic.ca` certificate-name validation. Missing real identity/password remain an explicit typed-null provisioning blocker; no insecure placeholder campus profile is installed. At the user's request, add a separate encrypted SenecaNET file containing explicit replacement markers, using only the existing public recipients and no decryption of the password/PSK file. Keep its source selector null until both values are filled locally and reviewed; the runtime helper rejects either marker if selected prematurely.

Select `pkgs.linuxPackages_latest` from **each host's own locked track**, with a major-7 assertion and independent validation. This deliberately supersedes the earlier explicit-minor recommendation in response to the latest-7.x request: after the 2026-09-10 update, both tracks provide 7.2.4. Keep upstream ZFS incompatibility failures enabled and evaluate Bastion's actual kernel module; a future incompatible update must stop. Do not silently pin an EOL kernel, allow broken packages or cross to 8.x. Retain native `i915` for observed Alder Lake-P, not experimental `xe` force-probing or an unobserved NVIDIA driver.

Use only JetBrainsMono Nerd Font for the requested monospace apps, retaining native Noto Color Emoji fallback. Enable native `programs.nh` on **ThinkPad only**, with its observed checkout path and cleanup disabled. It does not introduce standalone HM outputs or replace `just check`, readiness gates, explicit update review or operation authorization.

## Consequences

Desktop tests now cover only its supported unstable track and actual ThinkPad. Infrastructure/storage/SOPS/deployment fixtures still cover both tracks. Add offline secret-escaping tests, actual Wi-Fi manifest key-selection checks, native configuration checks and kernel/ZFS derivations. None establishes successful authentication, secret decryption, network/certificate acceptance, fingerprint enrollment, boot or hardware behavior.

KDE Connect opens TCP/UDP 1714–1764 and device discovery opens UDP 5353 on ThinkPad only. CUPS remains localhost-only with no shared queues. Preserve pairing control and review public-network exposure. Native greeter configuration replaces its system-owned TOML during a future authorized activation; Home Manager's no-force guarantee does not replace a system-state backup.

All commissioning/recovery/storage gates remain. Follow the [desktop acceptance procedure](../desktop.md) and [credential procedure](../../secrets/README.md). Record actual review before acknowledging any flag. No commit, activation or deployment follows from successful checks.

## Maintenance amendment — 2026-09-10

After the initial two-boot commissioning, the user requested a full dependency refresh plus explicit desktop behavior. Keep the same track boundaries and update the normal lock inputs together; advance the separately source-pinned sops-nix only after reviewing its own diff. Update exact Pi npm/browser XPI pins and hashes independently. Pi now defaults to `openai-codex/gpt-6-astra`; credentials remain mutable private state.

The resulting unstable update advances Claude Code, Herdr and Zed while their host-package boundary remains intact. Keep Home Manager on its legacy collision-checking activator rather than the new experimental Putter path. Preserve Zed's prior explicit-submit project search despite its new upstream default, retain the byte-identical reviewed Herdr Pi hook, and treat any still-running pre-update Herdr server/panes as mutable state requiring runtime review rather than automatic replacement.

The observed external EDID now supports a generic output policy without inventing connector or GPU topology: external outputs use their preferred modes in a top row, eDP-1 is centered below, and the lid disables eDP-1 only while an external remains. Enable 10-bit `hdredid` only when each live EDID advertises BT.2020, PQ and static HDR metadata; otherwise retain 8-bit sRGB. Preserve automatic GPU selection and VRR-off policy. The policy watches hotplug and configuration reloads so losing the last external while the lid is closed restores the internal panel and reloads reapply runtime layout/HDR rules. Only connected DRM-backed outputs count as externals, never Hyprland's virtual `FALLBACK` or arbitrary headless outputs. Parsing, command and IO failures stop processing rather than proceeding to disable the panel or silently retrying. Build/dry-run validation is not a modeset or runtime HDR/lid acceptance, and the accepted previous generation remains the fallback until a separately authorized maintenance activation.

Keep native Epson queue provisioning, but make `ensure-printers.service` manual-only with no boot target or restart-on-rebuild. Ordinary boots reuse persisted CUPS queues/PPDs; missing state requires explicit authorized provisioning while the printer is reachable. Do not recreate the upstream provisioning logic, probe/retry the network during boot or delete persistent state to enforce the declaration. See [review research](../research.md#display-and-printer-review-corrections--2026-09-10) and [printer procedure](../desktop.md#home-printer-provisioning).
