# ADR 0008 — Native desktop modules, private Wi-Fi, stock 7.x kernels

- Status: accepted; amends [ADR 0007](0007-thinkpad-desktop.md) and [ADR 0002](0002-nixpkgs-tracks.md) (maintenance amendments 2026-09-10/11 folded in)
- Date: 2026-09-09

## Context

The user requested reusing the current Ghostty, Herdr, Zed, Zen, Pi and Bitwarden preferences, fingerprint login/locking/sudo, SOPS-managed home/campus Wi-Fi and the latest available 7.x kernels. Approved optional tools: file/archive/document/image utilities, system/audio/network controls, Bluetooth, KDE Connect, printing/scanning and shell conveniences. No media player.

## Decision

**Desktop modules.** Remove unused stable Home Manager: the desktop integration imports the unstable `home-manager` pin only for its bundle and rejects stable composition; the bridge lives in `modules/desktop.nix` (ADR 0001 concern ownership). Servers retain stable Nixpkgs without HM. Keep class-checked deferred modules, host `pkgs`, `useGlobalPkgs`, `useUserPackages`, release checks and file-collision detection. Use native HM/NixOS options (Hyprland Lua, Noctalia, Ghostty, Herdr, Zed, Pi); Lua dispatcher expressions use the native inline-value escape hatch. Preserve Noctalia's isolated profile and one session owner.

**Authentication.** Native Noctalia Greeter (greetd underneath) with the UWSM session. Fingerprint PAM is narrowed to a dedicated graphical stack and sudo, ordered **password first**; greeter empty submission requests the alternative authenticator and never permits an empty account password; deny rules, console/SSH policy and keyring handling stay. Noctalia's lockscreen drives fprintd independently alongside password entry. Fingerprint templates and greeter/Bluetooth/printer system state have scoped persistence; `/home` needs no duplicate binds.

**Applications.** Port reviewed preferences and public pinned extension manifests — never credentials, vaults, browser profiles or arbitrary old desktop settings. Zen is a normal `zen-browser` flake input (default branch, pinned only in `flake.lock`) whose recipe is instantiated with the host's own `pkgs`, retaining its researched Firefox-wrapper passthru adapter and pinned XPIs. The desktop-only HM input is named `home-manager` (default branch, unstable follow). Pi declares pinned extensions in managed `settings.packages` and keeps safe project-trust/rewind settings; only `cursor-cli` is allowed by the desktop unfree predicate. The Claude bridge and its `claude-code` package/allowance were removed ([current Pi inventory](../pi.md)). Only JetBrainsMono Nerd Font is explicitly installed for the monospace apps, with native Noto Color Emoji fallback. Native `programs.nh` on ThinkPad only, with the observed checkout path and cleanup disabled.

**Wi-Fi.** Native NetworkManager `ensureProfiles` with system-owned, root-only runtime secrets (`*-flags = 0`) — no competing secret agent or Noctalia patch. A small offline-tested adapter escapes raw SOPS scalars for the systemd environment file and GLib keyfiles. Reuse MN-Home's encrypted PSK/profile UUID. SenecaNET uses PEAP/MSCHAPv2, the system CA bundle and `senecapolytechnic.ca` certificate-name validation; missing identity/password remain typed-null blockers, and the separate encrypted SenecaNET file keeps explicit replacement markers until filled and reviewed locally — the runtime helper rejects markers if selected prematurely.

**Kernels.** `pkgs.linuxPackages_latest` from **each host's own locked track**, with a major-7 assertion and independent validation. This supersedes the earlier explicit-minor recommendation. Upstream ZFS incompatibility failures stay enabled and Bastion's actual kernel module is evaluated: a future incompatible update must fail rather than pin an EOL kernel, allow broken packages or cross to 8.x. Native `i915` for the observed Alder Lake-P — no experimental `xe` force-probing or unobserved NVIDIA driver.

**Output policy (amendment).** External outputs use each EDID's preferred mode in one top row; eDP-1 is centered below; the lid disables eDP-1 only while a fresh external remains. 10-bit `hdredid` is enabled only when live EDID advertises BT.2020, PQ and static HDR metadata; otherwise 8-bit sRGB; VRR stays off; GPU selection stays automatic; no luminance or ICC values are invented. Only connected DRM-backed outputs count as externals, never Hyprland's virtual `FALLBACK`. Monitor updates use Lua `hl.monitor` through `hyprctl eval` — legacy `keyword monitor` is rejected by the selected Lua parser even with a zero CLI exit — requiring the exact `ok` reply (which only acknowledges a queued rule) and explicit `disabled = false` when enabling. The panel is disabled only after a fresh active physical external (enabled, DPMS-on, positive dimensions); initial sync waits for confirmed socket subscription; only one hotplug event family is handled to avoid duplicate syncs. Parsing, command and IO failures stop processing rather than proceeding to disable the panel or silently retrying. Applied rules are not rolled back. See [dated review evidence](../research.md) and [current status](../hosts.md#current-status).

**Printer (amendment).** Native Epson queue provisioning stays, but `ensure-printers.service` is manual-only — no boot target, timer or restart-on-rebuild. Ordinary boots reuse persisted CUPS queues/PPDs; missing state requires explicit authorized provisioning while the printer is reachable. Do not recreate upstream provisioning logic, probe/retry the network during boot or delete persistent state.

**Maintenance (amendment).** Track boundaries are unchanged: normal lock inputs, including sops-nix's default-branch input, follow the researched update procedure; review sops-nix's own diff before advancement. Pi npm/browser XPI pins update independently. Home Manager stays on the legacy collision-checking activator rather than the experimental Putter path. Zed's prior explicit-submit project search is preserved. Both Herdr Pi extensions were removed: Pi no longer reports session/prompt state to Herdr panes. The Herdr program remains unchanged; still-running pre-update server/panes are mutable state requiring runtime review.

## Consequences

- Desktop tests cover only the supported unstable track and actual ThinkPad; infrastructure/storage/SOPS/deployment fixtures still cover both tracks ([validation scope](../validation.md)). None establishes authentication, secret decryption, network/certificate acceptance, fingerprint enrollment, boot or hardware behavior.
- KDE Connect opens TCP/UDP 1714–1764 and discovery UDP 5353 on ThinkPad only; CUPS stays localhost-only with no shared queues. Native greeter configuration replaces the system-owned TOML during authorized activation; HM's no-force guarantee does not replace a system-state backup.
- All commissioning/recovery/storage gates remain; record actual review before acknowledging any flag.

See [desktop procedure](../desktop.md) and [credential procedure](../../secrets/README.md).
